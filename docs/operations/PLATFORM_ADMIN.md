# Platform 管理后台

Platform 自带的 `/admin/` 管理后台面向维护 Registry、加密信箱、Relay 与运行策略的运维人员。它只管理 **Platform 持有的基础设施状态**：注册记录、平台保存的签名密文、连接、平台策略及审计事件。Agent 本机的配对、联系人、审批、委托和会话由各自设备持有；Platform 管理令牌不授予这些业务权限。

## 管理能力与操作结果

| 范围 | 查看与诊断 | 管理动作 | 结果边界 |
| --- | --- | --- | --- |
| 平台 | 运行时间、进程与内存、监听地址、连接方向、策略、容量配置 | 修改可在线生效的策略；修改存储策略时重启 | HTTP 健康与概览仅证明服务可响应，不证明两端业务完成 |
| Registry | 有效 URN、Peer ID、地址、过期时间、存储声明 | 驱逐单条或逐项执行批量驱逐 | 驱逐不撤销 Agent 密钥或本机配对；所有者可以重新注册 |
| MQ | 每个收件人的未读数量与大小、密文元数据、已读历史、队列汇总 | 删除单封密文，或清空指定收件人队列 | 删除待收密文不可恢复；MQ 保存/ACK 均不表示收件人完成业务 |
| 连接 | 当前 Platform peer、连接方向、地址与协议 | 当前仅诊断；连接生命周期由网络协议管理 | 当前连接不证明远端具备存储能力或在线 Agent 已授权 |
| 审计 | 按级别、来源和内容过滤，按页查看操作与系统事件 | 通过受控管理 API 产生操作记录 | 审计是 Platform 的事件记录，不是外部交付凭据 |

管理台不提供任意 SQL、文件编辑或代 Agent 签名的入口。需要备份、恢复、证书、镜像或主配置变更时，使用[部署与升级指南](DEPLOYMENT.md)的服务器操作流程。这样管理后台能覆盖日常处置，同时保留身份、数据和部署边界。

## 设计约束

- **服务端事实优先。** 计数、策略与操作结果来自当前服务端响应；页面缓存只用于展示，不能凭点击次数推断最后状态。状态变更提交明确目标值，并在成功后重新读取。
- **读取有界。** 消息明细按收件人、状态、页大小和偏移读取，避免大型队列一次返回全部密文。概览中的待收数量、历史数量和已过期待清理数量分别呈现，不能混为送达数。
- **影响可见。** 驱逐、删除单封和清空队列分别说明作用范围；页面要求确认并展示实际删除数量。批量操作保留每项结果，失败项可重试。
- **失败不伪装成功。** 持久策略先写入数据卷再向页面报告成功；存储策略的重启安排、服务重连和最终恢复是不同阶段。审计记录操作，但不能替代数据库结果或 Agent 侧业务回执。
- **授权边界固定。** 单一管理员令牌只管 Platform。公开 Registry 的自认证所有权、MQ 加密与 Agent 本机的主人授权继续由各自的验证逻辑约束；管理台不能创建一个未签名的合法 Agent 身份。

## 进入与鉴权

1. 通过可信终端与 HTTPS 打开 `/admin/`，输入部署环境提供的 `PLATFORM_ADMIN_TOKEN`。令牌仅存在当前标签的 `sessionStorage`；退出管理台或关闭标签后清除。
2. 所有 `/api/v1/admin/` 请求在 `X-Admin-Token` 头中携带令牌。未配置令牌的服务拒绝管理请求；令牌不放在 URL 中，管理响应不缓存。
3. 令牌持有者拥有全部 Platform 管理权限。按[Platform 安全配置](../../agent-comm-platform/docs/guides/SECURITY.md)限制网络入口，并在运维人员变更时通过服务器环境轮换令牌。当前没有多管理员账户或按动作拆分的角色。

## 日常巡检与处置

先核对概览中的 Peer ID、存储与转发策略、Registry 数量、MQ 待收数量和最近审计事件。排查消息积压时从 MQ 汇总进入收件人队列，检查未读和历史的分页元数据、保存时间及到期时间。服务端不解密业务正文；管理台展示的密文内容不能据此判断业务是否成功。

针对单封异常消息，先核对收件人和消息 ID，再删除这一封。清空队列会删除该收件人的未读和已读历史，应先核对范围及备份。批量清理或驱逐逐项返回结果；部分失败时按失败项复查，不能将整个批次写成成功。修改转发策略时提交明确的目标状态并复读服务端结果，避免旧页面重复点击后反向切换。该策略持久化于 `platform_data` 卷内的 `admin-policies.yaml`，重启后仍生效。

更改 `store_user_data` 会清空 Registry 并触发 Platform 重启，以便节点按新策略重新注册；管理台收到成功响应只表示更改已持久化且重启已安排，还需等服务恢复后复查。调整已读历史保留天数不会立即物理删除所有旧记录，后台清理按周期执行。`0` 表示下一次清理时删除已读历史。具体接口和返回字段见 [Platform HTTP API](../../agent-comm-platform/docs/guides/API.md)。

## 验证与回退

上线前运行 Platform 的 Go API 与存储测试、管理台 Node 测试以及根仓库文档结构检查。在隔离环境验证驱逐、单封删除、清空队列、策略持久化及重启恢复；线上切换后优先做健康、令牌拒绝、只读管理端点、Peer ID/策略/队列计数与容器重启数检查。不要为了冒烟测试清空生产队列或注册表。

部署前对 Platform 数据卷中的 Registry、MQ、审计三个 SQLite 数据库，以及 Web 数据卷中的账户数据库做一致性在线备份，纳入 WAL 中已提交的状态；同时保存身份密钥、`admin-policies.yaml`、环境和配置，并记录旧镜像与源码提交。回退应用时保留切换后产生的实时写入；旧备份不应直接覆盖实时库。若已通过管理台更改策略，先核对策略文件与待回退版本是否兼容。每次实际发布的版本和验收范围写入[发布记录](../releases/README.md)，不从源码变更推断线上已经更新。
