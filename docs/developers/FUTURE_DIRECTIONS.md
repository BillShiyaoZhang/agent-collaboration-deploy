# 尚未实现的扩展方向

本页供设计与开发评审使用，记录值得保留的约束和后续验收目标，**不表示功能已排期或已发布**。现行协作能力以[架构说明](../architecture/COLLABORATION_AND_ATTENTION.md)和实际宿主能力为准。

## 外部执行，例如日历写入

当前会议协作可形成双方接受并同步的约定，尚不写入日历。若增加外部执行，需要独立于消息传输的执行适配器，声明固定能力和可核查的结果。双方接受同一执行计划；同意会议时间不自动授予操作个人日历的权限。计划需绑定约定版本、执行方、工具账户、截止时间、幂等键、成功证据和补救范围。

执行前重新核对本方授权、约定及资源版本。工具超时或进程中断后，应先按原业务 ID 查询真实结果；没有幂等或查询能力时不盲目重试。跨两个人的日历不能假定原子提交，部分完成要显示已发生的动作与待处理结果；取消或补救是新的受控动作。验收应使用真实双账号与故障注入，证明不会重复创建或误报完成。

## 代表权和再委托

当前对端接受事件由已绑定的端点签名，只能证明该端点的声明，不能独立证明其主人亲自签名。需要更强代表权时，应有独立受信签发者，以及绑定受众、具体动作、时效和撤销版本的凭据。工具回执可证明某项执行结果，不能代替主人授权。

如果以后支持再委托，每一跳都要有明确的父权限依据、受众、动作交集、期限、深度、环路和撤销检查。通信关系或图谱路径不能推导出主人授权。此方向需要单独的威胁模型和互操作验证。

## 关系事实与声誉

可把实际交互、对端自述和本方推断分开保存：事实带回执和来源，自述标为待核实，推断带样本、反例与适用场景。这些信息最多帮助改变沟通与核实方式，不能放大授权。端点换主人或绑定变化时，历史也不能继承权限。

若以后聚合平台声誉，需另行征得同意，仅共享可核验的最小证据。单边评价和第三方工具故障应明确区分；在申诉、更正、隐私、反刷分和撤回机制可用前，不上线公开通用评分。其验收不能用现有协作或提醒测试代替。
