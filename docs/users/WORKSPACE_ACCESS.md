# Ambient 本机工作区远程入口（合并建议）

此入口在独立提案副本中提供，尚未上线。它让登录用户通过云门户打开自己的 Ambient；Agent、App 数据、密钥和任务执行仍在用户电脑上。网页和默认 Widget Controller 在访问者浏览器运行。完整工作区授权与普通 Agent Comm 对话授权分别确认。

1. 在自己的电脑启动 Ambient，并在本机的远程连接设置中填写管理员提供的 Gateway 和云门户地址。
2. 选择期限和权限并生成一次性连接码。`workspace.control` 可读写自己的工作区并执行任务；附加 `workspace.manage` 才可远程管理 Provider、Coding Agent、Skill 和 capability。
3. 登录目标云账户，在云门户工作区入口领取一次性码；码五分钟后失效，领取后不可重复使用。
4. 回到原电脑 Ambient，核对账户、范围和到期时间，点击确认。仅在云端领取不会让云端获得访问权。
5. 在门户显示在线后打开工作区。打开链接只使用一次；下次访问从门户生成新链接。浏览器会话最多一小时，并且不能超过本机授权期限。

电脑需要持续开机、联网并运行 Ambient。离线不会取消已在本机运行的任务；恢复后读取同一任务的真实状态，不能把网络回执丢失当成需要重复提交。不同电脑的工作区使用不同域名，浏览器存储和 Cookie 独立。

在云门户或本机撤销连接后，远程请求和已经打开的连接立即失效。本机离线时，本机撤销先关闭本地通道；无法通知云端时也不继续使用原许可。已执行的操作不能通过撤销倒退。账号误领时不要在本机确认；先撤销本次连接并重新生成码。

Gateway 不持久保存中转的业务正文，但 TLS 在入口终止时，运营者仍能够处理明文请求与响应。现有 Agent Comm 云工作台的已授权同步副本使用原来的独立机制。完整数据边界和部署限制见[Gateway 提案设计](../architecture/WORKSPACE_GATEWAY_PROPOSAL.md)。
