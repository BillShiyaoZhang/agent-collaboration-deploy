# 2026-09-23 Web SQLite 单连接缓冲与慢轮询观测

r2 现网双账户探针的 154 次 HTTP 请求均成功，但在首装同步重叠窗口仍出现 4 次被重试吸收的 SQLite Code 5，且两次控制轮询接近 10 秒。本轮将单个 Web 容器的 Prisma `DATABASE_URL` 设为 `file:/app/data/prod.db?connection_limit=1`：同进程的数据库查询在连接池等待，避免 Web 自身多个连接同时争夺 SQLite 写入权。它也会串行化读查询，属于**进程内、受连接池超时约束的缓冲**，不是独立、持久且有容量上限的写队列。工作台已有的持久调度、租约和重复唤醒合并保持不变；用户发起的控制请求仍须先落库，再通过 Platform 投递，收到的响应也仍先落库再 ACK。

Web 同时新增控制轮询慢请求观测：仅总耗时达到 2 秒时输出固定字段的分段毫秒数，区分会话/数据库读取、Platform 邮箱请求、响应持久化、工作台投影与总时长。日志不含用户标识、Agent URN、请求 ID、密文或正文。这用于定位曾出现的约 10 秒尾延迟，没有改变控制协议、重试或确认顺序。
