T04 真人阶段失败的直接原因是 Agent 对已拒绝联系人的准确 URN 保留绑定，而当时生产 Web 只提供“新增联系人”，新建另一个 `contact_id` 会触发参数校验失败。正确重申请需要从原已拒绝联系人发起，沿用原 `contact_id`、别名和 URN，再产生独立的新好友请求。反方向发起后的 `connected` 仅用于继续真人 T05，不证明 Alice 当时遇到的 UI 缺陷已消失。后续 Web 修复已部署，**使用另一对 Codex 合成身份**完成了线上重申请复测；真人阶段的失败事实仍保留。

T05 的两条 Bob→Alice 消息时间相近、来自同一个 URN。Alice 曾报告已将原生回复 `t05-b-ack-bob-001` 标为已读，但随后按本机 Store 的消息 ID 对账，实际先读的是较新的 Bob Web 消息 `message-93c01ca4-0b2f-4a87-b5fa-8cf984caeebf`，原生回复当时仍未读。测试者刷新后只点击原生回复自己的按钮；最终**两条均已读，各自提醒均已解决**。目前证据说明卡片区分不够直观；没有证据表明 Web 把点击的一条错误写到另一条消息 ID。修复方向是显示可复制的精确消息 ID，并让已读按钮的可访问名称包含该 ID，再用测试核对 `inbox.mark_read` 的参数。
