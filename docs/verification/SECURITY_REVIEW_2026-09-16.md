# 2026-09-16 安全检查与修复

本次检查覆盖部署仓库、Web、Platform 与嵌套 SDK 的当前源码和依赖，所有复现使用临时身份、数据库或容器。检查完成时修改尚未发布；2026-09-17 已推送四仓源码并部署服务器服务，公开版本和验收结果见 [安全修复上线记录](../releases/SECURITY_RELEASE_2026-09-17.md)。公开安装包和已安装客户端没有自动升级。

## 确认的问题和处理

| 范围 | 问题与影响 | 修复 |
| --- | --- | --- |
| 平台管理页 | Registry 地址、URN、消息 ID 等外部数据进入 HTML/事件属性，可执行脚本并读取管理员令牌 | 分别编码 HTML 和 JavaScript 属性上下文，对实际渲染函数增加回归；管理员令牌仅允许请求头，不再接受 URL 查询参数 |
| 平台 HTTP | 任意客户端可伪造转发头绕过限流，限流器缓存无上限；配置的 TLS 证书没有实际启用 | 默认按 TCP 对端限流，仅显式可信代理可提供客户端地址；缓存有界；TLS 真实启用且加载失败停止监听 |
| 注册服务 | 旧签名记录能回滚新状态；P2P 第三方可复制他人的注册签名并替换未签名的地址 | P2P 注册校验连接身份属于注册者，内存及持久注册存储拒绝旧时间戳覆盖 |
| 网络协议 | Registry 的 EOF 读取、WoT/DR 帧长度及部分流缺少约束，可占用内存或连接 | 统一 1 MiB 消息/帧上限、读取超时与缺失响应检查；WoT 写锁内重复取锁导致的死锁一并修复 |
| 消息队列与 Relay | 队列批量读取、ACK 和过期时间不受充分限制；Relay 字节限制配置未生效、持续时间用于错误字段 | 按数量及总字节分页，限制 ACK 和 TTL；Relay 使用正确的电路字节/时间约束 |
| Web 密码 | bcrypt 只验证前 72 个 UTF-8 字节，长密码不同后缀可能被当作同一密码 | 新密码使用带随机盐的 scrypt，旧哈希成功登录后条件升级；输入上限 1024 UTF-8 字节 |
| Web 请求体 | 若干接口先完整读取再检查大小；认证 POST 无读取上限 | 流式累计实际字节，超限即取消；覆盖注册、NextAuth、连接、控制、工作区和通知接口 |
| 认证路径 | NextAuth 接受多余路径段，可能绕过只针对精确路径的代理限流 | 应用拒绝多余路径段，nginx 的注册/登录限流同时覆盖后缀路径 |
| 发布下载工具 | 摘要校验可缺省，资源名与 ZIP 路径可以逃逸安装目录，临时文件名可预测 | 强制 HTTPS 和 SHA256，禁止重定向降级，限制下载/解压体积及条目，校验便携文件名，仅提取受限 Markdown 文档 |
| 部署 | 空密钥仍可启动、默认回退公网 HTTP；Web 以 root 运行、构建降级 HTTP 软件源并单独安装未锁定 SWC | Compose 必填密钥和 URL；HTTPS 软件源、锁文件安装；迁移及 Web 进程前降权，兼容旧数据卷属主 |

现有账户范围数据库查询、同源写入校验、签名与加密信封绑定、推送目的地限制和本机显式配对边界也在审查范围内，未发现需要额外修复的直接绕过。秘密模式扫描未发现提交源码中的真实私钥或常见服务令牌；这不等同于对 Git 全历史、线上日志或主机密钥库的审计。

## 依赖处理

- Web 从 Next.js 14.2.35 升到 15.5.25，NextAuth 升到 4.24.15，React 及类型升到 19.3.0，并完成异步路由参数、instrumentation 配置与 ref 类型适配。
- 更新兼容的传递依赖；为 Next 固定的旧 PostCSS 添加安全版本覆盖，并更新 NextAuth 4 未使用的可选 `@auth/core` 依赖。`npm audit` 从 15 项（3 critical、8 high、2 moderate、2 low）变为 0 项；Linux 容器中的 `npm ci` 也报告 0 项。
- Go 最低工具链与平台构建镜像升级到 1.26.8，DTLS/WebTransport 升到对应修复版本。扫描区分可达调用和仅被导入/依赖的告警，不将“无可达漏洞”描述为所有模块无告警。
- Platform 运行基础镜像从旧补丁 Alpine 3.21.3 更新至 3.24.1，并使用官方 HTTPS 软件源；版本与维护状态按 [Alpine 发布记录](https://alpinelinux.org/releases/) 核实。检查阶段受下述 Docker 镜像下载限制；完整生产镜像已在 2026-09-17 发布环境重建并验收。
- Platform 的 Windows 与 Linux/amd64 扫描均为 0 条可达漏洞，仍有 3 条已导入和 17 条已依赖但未调用的告警。SDK 保留一项 [GO-2024-3218](https://pkg.go.dev/vuln/GO-2024-3218)：Kademlia DHT 内容审查风险，上游所有版本暂无已知修复。实际消息发现使用签名 Registry/MQ，因此将 Agent 的 DHT 改为默认关闭；显式 `EnableDHT: true`、独立 DHT API 和示例仍有该风险，静态扫描仍会报告。此项是运行时缓解，不能声称已修复上游漏洞。
- OpenClaw 连接器 `npm audit` 为 0 项；Python runtime 无第三方运行依赖。Hermes 连接器使用宿主依赖范围（包括 `aiohttp>=3.14.3,<4`），没有独立环境锁，因此不对未知宿主已安装依赖给出“零漏洞”结论。

版本选择依据 [Next.js 支持策略](https://nextjs.org/support-policy)、[2026 年 8 月安全公告](https://nextjs.org/blog/august-2026-security-release)、[Auth.js 安全公告](https://github.com/nextauthjs/next-auth/security/advisories/GHSA-7rqj-j65f-68wh) 和 npm/Go 官方漏洞库的当次扫描结果。

## 升级注意事项

- 发布时先推送子仓，再固定父仓子模块引用。2026-09-17 已提交、推送并重建服务端镜像；公开安装包及已安装客户端仍需单独更新。
- 保留原 `NEXTAUTH_SECRET` 与一致的数据库备份。scrypt 升级后的账户无法由旧 bcrypt-only 镜像验证，回滚版本必须保留新验证器。旧 bcrypt 的被截断后缀无法恢复，尚未登录升级的账户保留旧行为。
- 公共流量通过 nginx，3000/8080 保持内部可见。可信代理范围需匹配实际专用网络，最好收窄到 nginx IP；不受信任容器不得加入此网络。应用直接对公网开放时需要等价的限流入口。
- P2P 不再允许第三方替其他身份发布注册；管理 API 不接受查询参数令牌；发布下载工具拒绝 HTTP、缺失摘要和路径式安装名。客户端若依赖这些旧行为必须同步更新。
- 依赖 DHT 的 SDK 使用方必须显式启用，并自行评估上述未修复的上游风险。默认 helper 的 Registry/MQ 通信路径保持可用。
- 本次未对生产流量、真实宿主会话、云权限、Git 全历史、在线数据备份或完整容器系统包执行渗透/取证。测试结果支持记录中的源码与本地场景。
