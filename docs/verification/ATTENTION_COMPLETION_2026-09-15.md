## 本轮实现

- Runtime 0.1.2 / Hermes connector 1.5.3 / companion 1.1.1：本人可读完整背景，实时核对确切授权范围，恢复或新建持久关联会话；每个恢复请求最多自动提交一次。结果不确定时保留原会话，不自动重发。
- 原生确认按当前授权问题的实际期限等待；到期、取消、停用或问题失效时清理对应卡片。迟到回答不获得授权，不延长源端授权期限。
- 处理会话名称保留真实会话 ID 后缀，满足宿主的标题唯一约束。已有草稿先恢复；创建、命名、绑定、打开失败分别提示阶段，不暴露原始错误。
- 交接提示提供合法的工具调用 JSON，将事项定位信息明确分开，避免模型把定位信息作为工具参数。
- 只有本人通过原生问题批准的有限会议程序才可后台运行。固定提议、符合已批准范围的接受以及有限协议回执受版本、期限、运行和发送预算约束；撤销、越界与未知发送停止并生成待办。
- Web：持久 Web Push 队列、服务工作线程、订阅撤销、账号隔离、有限重试、前台延后、测试与回执诊断。
- Hermes 宿主：修复 React Compiler 缓存未依赖动态路由注册表的问题，插件晚加载后可以进入待办页。源补丁及 renderer 的旧文件均保留备份。

## 能力边界

- Web Push 需要该设备浏览器明确开启；浏览器、系统权限、静默策略、厂商推送服务可达性仍影响显示。服务已接收、SW 调用了显示接口、本人实际看见横幅是不同证据。
- 关闭网页后已经显示的通用 OS 通知可能保留；点击后读取最新状态，过期条目不能批准。部分浏览器也可能生成自己的通用提示。
- Hermes 桌面通知依赖桌面运行；消息接收与已批准的有限协作程序依赖 Gateway/helper 运行。
- 当前会议完成表示双方约定已同步；尚未接入真实日历写入。对端代表权为对端声明，不是独立验证的主人签名；没有凭声誉或历史成功自动扩权。
