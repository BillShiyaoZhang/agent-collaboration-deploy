# 2026-09-25 T21 双 helper、外部 Push 与断线恢复补测

本记录针对[T21 执行卡](../testing/ADDITIONAL_CASES_2026-09-24.md#t21有界并发慢轮询与断线恢复p1发布观察-p0)中先前缺失的三项：两套真实 helper 同时工作、外部 Web Push、HTTPS 请求中断后的结果恢复。使用独立合成身份和账户，不向真实用户发送消息。以下是**两个环境中的定向样本**，不能把它们相加当成一次涵盖所有路径的生产负载窗口。

| 范围 | 环境与版本 | 实际结果 |
| --- | --- | --- |
| 双真实 helper 与 Web 重叠并发 | 本机隔离 E2-V：Windows 双 helper，Linux Docker 原生命名卷；Platform 镜像 `sha256:0090f49dfa7d42b281633686cff062c7362faf6df118ff4fb45db4fcabc7f6ad`，Web 镜像 `sha256:7b3418adc70dfd500e1b8c5488b6a53812f4fc3aa4fd6e1c8e8c12160e678869` | 两端各发 32 条，64/64 HTTP 202、64/64 平台签名回执、两端各解密并 ACK 32 条；另有 Web 176/176 个请求返回预期状态，最多 12 并行。 |
| 两端 Web 受管控制消费 | 同一隔离镜像的补充样本；两个合成 Web 账户各绑定独立真实 helper | Alice/Bob 同时各提交 `contacts.list`，各自 helper 取回正确请求，RemoteBridge 处理并走受管响应路径；Web 双方均为 `complete`，同 ID 重查一致，ACK 后不重投。两边自动 `capabilities` 请求也各完成一次。 |
| 已提交但未知结果的 TLS 断线 | 同一隔离 HTTPS Web 栈，一次性客户端连接 | 服务端持久写入已由独立 GET 观察到、客户端尚未读取响应字节时断开；以原唯一 URN 查询到 1 行，重复 POST 返回 409，随后 12 次读取均 200。 |
| 只传输部分请求体后断线 | 同一隔离 HTTPS Web 栈的补充样本 | 声明 `Content-Length: 98`，仅发前 49 字节后断线：该 URN 无业务记录；同 URN 完整重试返回 201、恰一行，再重复返回 409。 |
| 真实外部 Web Push | epoch 2 时的生产 HTTPS Web（镜像 `sha256:8676bde7036540ce2bb6049d1f2789d0b80ee9757548dc76caf02b3f3ea85496`），独立临时 Edge 浏览器资料和一次性 `@example.invalid` 账户 | 浏览器取得实际 Windows Push 订阅；关闭网站页面后，两轮测试最终被 Windows 推送服务接收，Service Worker 报 `displayed`，浏览器通知对象计数为 1。 |

隔离 Web 窗口预声明 16 次写入、160 次读取；实际写入 `201×16`，代理列表 `200×80`、策略读取 `200×48`、工作台读取 `200×32`，无意外 HTTP 5xx。写入 p95 为 0.265 秒，三类读取的 p95 分别为 0.093、0.172、0.141 秒，均无达到 2 秒的请求。三个测试容器重启数均为 0；日志中未见 `P2024`、`P1008`、`SQLITE_BUSY`、`database is locked`、`Code 5`、`disk I/O error`、panic。停机后复制命名卷进行离线核对，四份 SQLite `quick_check=ok`；MQ 中本轮 64 条 ID 均唯一且已读，Web 中断标识只有一行。

外部 Push 经真实 WNS 端点 `wns2-ln2p.notify.windows.com` 投递。两轮第一次投递尝试都曾显示 `push_service_unavailable`，之后有限重试成功，其中第二轮约 43 秒。`displayed` 和浏览器通知对象只证明 Service Worker 接受了显示请求，**不是某个人亲眼看见系统横幅**。测试订阅已在服务端撤销，浏览器已退订、关闭并删除资料。隔离 Chrome 的 `PushManager.subscribe()` 在已授权且 Service Worker 活跃时仍超时，因此本次不能声称 Chrome 厂商链路通过。

首轮曾在 Windows 宿主并行读取 bind-mounted SQLite，出现 `disk I/O error`、在线计数前后矛盾。失败样本保留，没有当作产品通过或直接定性为产品缺陷；最终轮改用 Linux Docker 原生命名卷，在线只按 API、真实 helper 回执判定，停机后才读数据库，结果如上。最终轮测试容器、网络、命名卷和临时私钥已清理。

双边受管控制补充样本停机后四库 `quick_check=ok`。离线 Web 库中，**本轮两条显式 `contacts.list` 均为 `complete`**；合成运行时停止后新产生的两条后台 workspace-sync `contacts.list` 仍为 `pending`，不能写成业务完成。Platform 对应 4 条受管请求均有持久读取标记。另有两条后台 `capabilities` 的完成证据在在线结果中。最初离线断言把全部 `contacts.list` 都要求为 `complete`，因此失败；按显式请求 ID 收窄断言后通过，失败结果仍保留。补充样本同样未出现容器重启；临时容器、网络和命名卷已移除。

边界：双 helper 使用真实进程和本机 Platform HTTP，TLS 注入发生在 Web HTTPS；隔离 Platform 镜像不同于当时线上运行镜像，新的 Web 镜像与最终线上 Web 镜像相同。Web 控制请求由真实 helper 收件、RemoteBridge 处理，没有启动 Hermes Gateway 或调用模型。外部 Push 在 epoch 2 生产合成账户上单独执行，当时 Web 镜像是上一版；本次 Web 更新只涉及安装说明和测试，没有改 Push 运行时代码。Push 不属于 176 请求重叠窗口。两种断线分别验证“服务端已提交但客户端未知”和“请求体不完整、服务端不应提交”；它们不能证明每种网络中断时序都无故障，也不是生产环境的破坏性故障注入。证据为忽略提交的 `build/t21-compliance-isolated-20260925/{helpers-result.json,result.json,managed-controls-result.json,offline-result.json,offline-controls-final-result.json,infra-result.json,infra-controls-result.json,cleanup.json}` 与 `build/t21-external-push-20260925/result.json`。
